# devto-mcp

[![CI](https://github.com/copyleftdev/devto-mcp/actions/workflows/ci.yml/badge.svg)](https://github.com/copyleftdev/devto-mcp/actions/workflows/ci.yml)
[![License: MIT OR Apache-2.0](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](#license)
[![tip](https://img.shields.io/badge/tip-%40copyleftdev-ff69b4.svg)](https://tokentip.to/@copyleftdev)

An MCP server for authorship on [DEV](https://dev.to), with the platform's real rules built
in rather than discovered one rejection at a time.

The value is not in wrapping ninety-nine endpoints. dev.to's rules live in Rails validators,
Pundit policies and a Rack::Attack initializer — **none of which appear in the OpenAPI
description** a code generator would consume. A client built from the published contract
learns them from 422s, at a budget of one write per second. This one knows them before it
sends anything.

## The four walls

Read from [`forem/forem`](https://github.com/forem/forem) at commit `ac54b3b` and verified
against the live API. Each of these fails quietly rather than loudly, which is why they are
worth stating.

**API v1 is opt-in by header, not by path.** Without
`Accept: application/vnd.forem.api-v1+json` the identical URL serves the deprecated v0
controller — which does not route unpublish, semantic search, reactions or surveys — and
returns 200. Every response here is checked for the `Warning: 299` stamp Forem puts on v0
replies, so a lost header is an error rather than a silently wrong contract.

**The API key is unscoped and all-or-nothing.** It carries the account's entire identity and
every privilege it holds. There is no read-only variant and no way to grant "may draft but
may not publish", so *this server is the only place that boundary can exist*. See
[Permissions](#permissions).

**dev.to publishes obligations for automated clients** at
[llms.txt](https://dev.to/llms.txt) — accurate AI disclosure, per-action authorization,
honest client identity. This server holds you to them.

**The rate limits are strict and invisible.** 30 reads per minute, 3 per second, 1 write per
second, counted against the IP *and* the API key simultaneously. An authenticated request
returns no `X-RateLimit-*` headers at all, so the budget is modelled locally and reported by
`whoami`.

## Install

```sh
cargo install --git https://github.com/copyleftdev/devto-mcp devto-mcp
```

Then register it. A key is generated by hand at
[dev.to/settings/extensions](https://dev.to/settings/extensions) — there is no programmatic
way to create one.

```sh
claude mcp add devto -s user -e DEVTO_API_KEY="$DEVTO_API_KEY" -- devto-mcp
```

Without a key it still runs, serving public reads and the offline validator.

## Permissions

Everything is off unless the account holder turns it on.

| Variable | Default | What it grants |
|---|---|---|
| `DEVTO_API_KEY` | unset | Reading your own work, drafting, editing. |
| `DEVTO_PUBLISH` | off | Making a draft visible. |
| `DEVTO_ALLOW_NO_AI_CLAIM` | off | Sending `ai_disclosure_level: no_ai`. |
| `DEVTO_BASE_URL` | `https://dev.to` | Point at another Forem instance. |

`ai_disclosure_level` is a **required argument with no default** on every write. Silence
would record `not_disclosed` on the article — a claim about provenance made by saying
nothing.

`no_ai` needs its own permission because a tool call cannot certify that a human wrote
something without meaningful AI assistance, and dev.to is explicit that a human reviewing
generated text does not make it human-authored. An account holder who wrote the piece
themselves sets the variable and the claim goes through.

## Tools

**Free — no network, no budget**

- `validate_draft` — every rule dev.to enforces, checked offline. Iterate here until clean.
- `analyze_readability` — six scores over the *prose*, with the share it measured stated.
- `analyze_structure` — outline and its gaps, paragraph lengths, code and link density.
- `forem_reading_time` — the figure dev.to will print, and the one over prose alone.
- `whoami` — account, permissions, and remaining rate budget.

**Reading**

- `my_articles` — the only way to reach your own drafts.
- `get_article` · `read_comments` · `list_tags` · `my_analytics`
- `search_articles` — `feed`, `keyword`, or `semantic` in one tool.

**Writing** — validated locally first, so a rejection costs no request

- `create_draft` · `update_article` · `publish_article` · `unpublish_article`

Deliberately absent, because they are impossible rather than unimplemented: **writing
comments** (no endpoint exists in any API version, and llms.txt asks clients not to automate
it), **reactions** (admin keys only), **image upload** (browser session auth only), and
**delete** (dev.to has none).

## Resources and prompts

The half of MCP that carries what a schema cannot.

| Resource | What it holds |
|---|---|
| `devto://liquid-tags` | All 74 registered liquid tags, grouped, with accepted hosts. Invisible to the API description. |
| `devto://frontmatter` | Which front matter keys override which API fields, and the three ways a body block silently changes your article. |
| `devto://constraints` | Rejections, and separately the things dev.to accepts *while doing something else*. |
| `devto://governance` | llms.txt's obligations and the disclosure ladder. |

Prompts: `draft-post`, `pre-publish-review`, `post-performance`. They encode the order of
work — research before writing, validation before the write, and the account holder's
decision last.

`scripts/refresh-knowledge.sh <forem-checkout>` re-derives the liquid tag catalogue from
source, so `git diff` afterwards is exactly the upstream drift.

## Text analysis, and why the denominator is the point

A readability score computed over a dev.to post is mostly measuring the code. The tools here
segment the document first and say what fraction of it they measured:

```json
"prose": {
  "words": 1011, "total_words": 1482, "share_percent": 68.22,
  "excluded": { "code_blocks": 13, "code_lines": 51, "inline_code_spans": 11,
                "headings": 11, "liquid_tags": 0 }
}
```

That is a real article of the author's: a third of what dev.to counts as its text is shell
transcripts and headings.

Across the author's own 30 published articles, **23.8% of the words dev.to counts are not
prose**. Counting them inflates Coleman–Liau by 2.26 grade levels on average and 6.88 at
worst. **28 of 30** articles have an overstated reading time, the largest by five minutes.
Nobody reading "grade 13" would know it was computed over a shell transcript.

Block quotes count as prose — a reader reads them. Headings do not: they are structure, and
counting them flatters the score.

### The numbers are checked against something that is not us

"We implemented Flesch–Kincaid" is not a claim anyone should accept. Every metric is verified
byte-for-byte against an independent oracle, and the fixtures are checked in so CI proves it
without Python or Ruby installed:

| Checked | Against | Corpus |
|---|---|---|
| Word, letter, sentence and syllable counts | Python `textstat` 0.7.13 | 58 documents |
| Six readability formulas | Python `textstat` 0.7.13 | 58 documents |
| Hyphenation positions | `pyphen` | 20,854 words |
| Forem reading time | dev.to's own published figure | 30 articles, **30/30** |
| Forem's word count | Ruby's `split(/\W+/)` | 31 cases |

Divergence is a defect in ours until proven otherwise. It has been three times so far: the
CMUdict edition (`textstat` reads NLTK's older release, which gives `extraordinary` five
syllables where upstream master gives six), `letter_count` stripping apostrophes that the
word count keeps, and Ruby's ASCII-only `\w` making `naïve` two words.

Gunning Fog, Dale–Chall and Spache are deliberately absent: all three need a word list whose
1948 provenance is not worth the licensing question for one metric.

### Datasets

`crates/devto-text/data` carries CMUdict (123,455 entries, BSD-2-clause, compiled to a
660 KB `fst`) and `hyph_en_US.dic` (Liang's TeX patterns, BSD-style). Both are attributed in
that directory. They are why the binary is 5.3 MB rather than 4.0.

## A few things the validator catches that nothing documents

- The body limit is **800 KB of bytes**, not characters.
- The title limit is measured with **every whitespace character stripped**.
- Tags are letters and digits only — `machine-learning` is invalid, `machinelearning` is not.
  Diacritics are fine; `español` is a real dev.to tag.
- **Front matter in the body overrides the payload.** A `title` key with no `series` key
  silently removes the article from its series.
- One tags entry containing a comma becomes **several tags**.
- `published_at` is **discarded without complaint** once an article is published.

## Layout

```
crates/devto-core     Types and the offline validator. No I/O, no async, and no ambient
                      clock — validate() takes the time as an argument.
crates/devto-client   HTTP. Version header, rate budget, caching, error mapping. The ureq
                      and wall-clock adapter is isolated in one file behind two traits.
crates/devto-text     Segmentation and text metrics. Pure, no I/O, no clock, like core.
crates/devto-mcp      The server: dual-era protocol, tools, resources, prompts, permissions.
docs/                 The research this is built on.
```

## Protocol

Ships **dual-era**. MCP revision `2026-07-28` removed the `initialize` handshake, but the
clients that exist today still open with it and cannot fall forward — a spec-perfect
modern-only server fails to connect outright. The era is decided by how the client opens and
held for the process.

## Development

```sh
./scripts/gate.sh
```

fmt, clippy with `-D warnings`, the full suite, and `cargo mutants` to **zero survivors**.
The script exports `CI=1` so the property tests derandomize: with random draws a mutation
score is noise, because cargo-mutants counts any failing suite as a kill.

The sweep runs through `scripts/bounded-mutants`, which holds it inside a cgroup with an
enforced CPU and memory ceiling — a quarter of the machine by default, `MUTANT_CPU_BUDGET`
to change it — and takes a per-repo lock so two runs cannot collide. cargo-mutants has two
independent parallelism knobs and bounding one bounds nothing: `-j` caps concurrent mutants
while `--jobserver-tasks` caps build tasks across all of them and defaults to `nproc`. Both
are derived from the one budget here so they cannot drift apart.

Three files are excluded from mutation, all because nothing in them can be killed by a unit
test, and each is kept deliberately thin because of it: the ureq and wall-clock adapter, the
stdio loop, and the one-shot CMUdict build script.

`cargo run -p devto-client --example live_check` exercises the read path against the real
API.
